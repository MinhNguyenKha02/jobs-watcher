# Relations Coverage Rule

## Purpose

Defines coverage requirements for `relations.source.ts`.

This file owns:

* recruiter vocabulary coverage
* ATS vocabulary coverage
* retrieval density
* lexical saturation
* bilingual recruiter-language coverage

This file does not own:

* anchor semantics
* relation structure
* template generation
* ontology definition

Those are owned elsewhere.

---

## Coverage Ownership

Anchor meaning is owned by:

* profile.source.ts
* anchors.rule.txt

Relation structure is owned by:

* relations.definition.rule.txt

Coverage quality is owned by:

* relations.coverage.rule.txt

---

## Coverage Goal

Every capability anchor must maximize:

1. recruiter search coverage
2. ATS search coverage
3. LinkedIn recruiter search coverage
4. exact phrase retrieval coverage
5. bilingual recruiter-language coverage

while preserving:

* anchor meaning
* abstraction boundaries
* vendor neutrality at capability level

---

## Coverage Layers

Every capability anchor should contain vocabulary from multiple retrieval layers.

### Precision Layer

Canonical recruiter-recognizable capability vocabulary.

Examples:

api development

service integration

workflow orchestration

database design

### Market Layer

Alternative recruiter wording observed in job descriptions.

Examples:

backend API development

API implementation

business process automation

external system integration

### ATS Layer

Vocabulary commonly searched in ATS systems.

Examples:

REST API development

event-driven workflow

database schema design

query performance optimization

### Recall Layer

Technology, framework, protocol, and vendor vocabulary.

Stored only in:

retrieval_associations

Examples:

Kafka

RabbitMQ

Temporal

PostgreSQL

Docker

## Lexical Saturation Rule

Generate recruiter surfaces until additional surfaces no longer provide meaningful recruiter-search coverage.

Coverage sources:

* job descriptions
* ATS terminology
* recruiter search terminology
* LinkedIn recruiter terminology

Prefer market-observed wording.

Avoid ontology-only wording.

---

## Bilingual Coverage Rule

Vietnamese and English surfaces must express the same capability.

Coverage density should remain approximately equivalent across languages.

Do not require literal translation.

Prefer recruiter-natural wording.

---

## Retrieval Association Density Rule

retrieval_associations should include:

* technologies
* frameworks
* protocols
* architectural terminology
* vendor products

commonly associated with the anchor.

The goal is recall expansion.

The goal is not capability definition.

## Coverage Acceptance

A relation node passes coverage validation only if:

1. recruiter coverage increases
2. ATS coverage increases
3. retrieval recall increases
4. bilingual coverage exists
5. lexical density is sufficient
6. anchor meaning remains unchanged

## Retrieval Definitions

Surface

A recruiter-visible phrase.

Association

A retrieval-only phrase.

Hit

An Aho-Corasick phrase match.

Coverage

Percentage of job descriptions
containing at least one phrase.

Density

Hits per job description.

Frequency

Phrase occurrence count
across corpus.

Freeze Spot

Phrase with zero observed hits.

Dead Phrase

Phrase with hit rate below threshold.
